# 前端质量检查与改进

检查日期：2026-10-04。对象：Chronolume 2.1.8 工作区中的 React 前端。

## 范围与判断

本项目是面向 Codex 用户的离线本地分析桌面应用。保留现有冷色仪表盘、紧凑导航、全局筛选与按页懒加载，重点修复统计可读性、操作反馈和跨页面一致性。覆盖总览、项目、会话、模型及价格、工具活动、数据诊断和设置。

此次未调整后端统计、定价计算、数据保留、导出结构和隐私规则；未变更依赖或平台支持声明。

## 已处理的问题

| 原有问题 | 改进 |
| --- | --- |
| 总览日均指标挤在一行，窄窗口及英文放大字体易拥挤 | 指标分行，峰值日期保留完整宽度；页头、操作区及设置行合理换行 |
| 部分深色辅助文字、浅色图标和状态文字不易辨认 | 统一辅助文字与反馈颜色、焦点边框，修正浅色状态与图标 |
| 导出、价格操作、工作区与偏好保存失败缺少反馈 | 统一处理中、成功、错误和重试提示；兼容 Tauri 序列化的脱敏错误对象 |
| 日期和价格输入可产生无效请求 | 校验日期顺序、非负价格与整数空闲间隔；错误输入保留草稿，日期保留未编辑端点的精度 |
| 筛选、排序、方向变化后分页可能停在空页 | 统一分页状态、重置及页数缩小后的纠正；搜索查询合并为 200 ms 防抖 |
| 刷新失败会隐藏已取得的数据；事件可能短暂显示其他会话的数据 | 保留已有列表并显示错误；事件占位数据限定到同一会话；刷新反馈不插入可见布局行 |
| 详情、编辑和价格预览缺少一致的键盘行为 | 统一对话框、初始焦点、焦点限制、Escape 和关闭后焦点返回；处理中阻止关闭 |
| 维护操作在后台索引中仍可点击 | 依据同步状态禁用冲突操作；清空通过明确的应用内确认完成，失败保留确认框 |
| 数据页加载时会暂时显示数据库“异常” | 未取得诊断时显示未知值，数据源状态等待诊断结果 |
| 图表仅通过颜色和鼠标提示呈现具体值 | 增加键盘可展开的数据表；展开前不创建数据行，保留 reduced-motion；最后一个趋势序列明确禁用隐藏 |
| PNG 始终使用暗色背景，独立 SVG 丢失 CSS 变量 | 使用当前主题背景，序列化前解析图表颜色 |
| 自定义实时范围仅在再次查询时推进 | 实时范围每 30 秒更新查询；固定结束时冻结当前时间 |
| 本地价格或工作区设置修改后，其他页面可能保留旧缓存 | 统一相关用量查询的失效范围 |
| 浏览器空预览容易被理解为已经读取本机数据 | 明确预览能力及桌面入口，禁用需要桌面运行时的操作 |

## 兼容性处理

Tauri 在 macOS 使用系统 WKWebView，运行时能力随系统 WebKit 变化，见 [Tauri WebView 说明](https://tauri.app/reference/webview-versions/)。WebKit 在 Safari 15.4 才加入原生 dialog 支持，见 [WebKit 官方发布说明](https://webkit.org/blog/12445/new-webkit-features-in-safari-15-4/)。因此保持项目 macOS 12 支持声明时，不能无条件依赖 `showModal`。

对话框提供特性检测及回退：背景遮罩、隐藏背景的辅助技术可见性、Tab 焦点限制、Escape、焦点恢复和滚动锁定。视口高度同时提供 `vh` 与 `dvh` 路径。回退分支已在 Chromium 中通过移除原生方法验证；这不等同于旧 macOS 真机验收。

## 实际验证

- TypeScript、ESLint、生产构建和 Git 差异空白检查通过。
- Vitest：14 个测试文件、40 项测试通过，覆盖原有流程、日期校验、分页、导出取消及失败、设置保存失败、清空确认和弹窗回退。
- Chromium 154.0.8037.93：七个主页面在 1440、1100、720、390 px 宽度下完成 28 组布局检查，未见整页横向溢出或缺少名称的可操作控件；列表保留自身可滚动区域。
- 最小桌面窗口 1100×680：工作区选择、别名编辑、会话详情、价格编辑和设置流程检查通过；Tab、方向键、Escape、焦点返回及错误后重试通过。
- 七个页面在英文、暗色、135% 字体缩放下的 1100 px 宽度检查通过。
- 深浅主题 PNG 均成功生成并解码，背景颜色符合当前主题；结构化导出成功反馈通过。
- 图表数据可通过键盘展开与折叠；30 行测试趋势在折叠后不保留表格行。
- 页面运行检查未捕获异常；截图与临时验证脚本保存在被 Git 忽略的 `artifacts/`。

浏览器检查采用仅含人工统计的隔离 IPC 测试数据，未对用户真实分析库执行清空、价格修改或导出，也未访问账号凭据。

## 验证边界

首次前端检查时，本机没有安装 Playwright WebKit 运行时，未执行 WebKit 浏览器检查，也尚未打包安装器。后续 2.1.9 发布已完成 Windows 打包、安装及便携启动检查，详见 [打包记录](packaging.md)。真实 WebView2 中七个页面的导航与内容显示检查通过，保留用户原有分析库和偏好。

桌面导航检查不等同于真实数据下所有编辑、导出及维护操作的端到端验收。未进行旧 macOS WKWebView、系统屏幕阅读器及高对比度模式的人工验收，这些仍需要在对应设备上复核。

此次不宣称后端索引速度、真实数据库性能或 macOS 分发质量得到提升。前端保留现有服务端分页和图表按需加载；改进集中在请求节制、可读性、状态完整性和交互稳定性。
