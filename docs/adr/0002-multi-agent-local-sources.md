# ADR 0002：多 agent 本地数据接入

- 状态：已接受
- 日期：2026-10-26
- 依据：用户确认同时接入 Claude Code、OpenCode，随后追加 DeepSeek Harness，默认合并展示、独立 agent 筛选、同路径项目合并、子会话独立统计、并行时间累加，并保留只读离线边界。

## 决策

`UsageSource` 继承原来源的 `detect/plan/stream` 边界，`CodexSource` 保留为兼容名称。生产使用 `MultiAgentSource` 编排 Codex 和新增来源；每个解析器只输出现有结构化记录及必要的缓存写入、报告成本和父会话元数据。查询、索引、保留、导出继续共用现有实现。

agent 由稳定会话命名空间导出。Schema 5 为既有记录赋予 `codex`，不重命名历史 ID；新会话使用 `claude:`、`opencode:`、`dsh:`。生成列避免 agent 与会话 ID 之间出现不一致；每日全局汇总把 agent 加入主键。Schema 6 扩展 DeepSeek Harness 身份及每日汇总约束，保留 Schema 5 三个来源的会话与摘要。工作区身份继续由原路径规则决定，不按 agent 拆分。

模型提供方保持独立。旧 Codex adapter 继续使用原有 `openai/custom/unknown` 规则，新增来源保留原生提供方；查询只兼容已知的历史 `codex_local_access` 别名。用户定价也按实际提供方保存。Anthropic 标准价格随内置快照交付，不新增在线账户或自动价格接口。

## 对 ADR 0001 的来源限定

Codex 的安全字节偏移、流式内存与追加吞吐约束继续适用。新来源中同一消息会在后续记录或数据库更新中修正已报告用量，直接把每条追加当作新 delta 会多计。因此新 adapter 首版按受影响会话重建**仅含结构化字段**的内存快照，在事务中替换该来源的派生统计。不会把完整文本、工具参数或整库内容载入快照；内存规模取决于一个会话的消息统计数量。此策略不宣称达到已有 Codex benchmark 结果。

Claude Code 合并流式重复消息及工具 ID；OpenCode 读取 JSON 与 SQLite 的并存记录，并确定数据库、新表的优先级。SQLite 只读查询显式抽取统计、模型、时间和工具名；不选择正文列或原始标题。取消新 adapter 的重放时回滚整个来源事务，下一次重新处理该来源。

## 验证

合成端到端用例覆盖跨 agent 同名会话、共享项目、父子关系、流式重复修正、旧 JSON/SQLite 并存、v2 消息、WAL 更新、事件保留及改价、缺失原生计时、取消、损坏源隔离和敏感标记不落库。迁移用例保留 v4 Codex ID、汇总、别名、价格覆盖和设置。真实新 agent 数据、macOS 原生窗口与大规模性能仍需独立验收。

DeepSeek Harness 共用标准化统计快照，使用 Zstandard 流式解压，不依赖本机 dsh/Node 命令，不安装 hook 或改动源记录。优先读取最新规范代际，按原生请求槽位保留最后用量样本，重试保留独立槽位；继承边界排除父记录，恢复边界不丢弃既有统计。提供方保持原样，价格通过既有本地配置维护。
